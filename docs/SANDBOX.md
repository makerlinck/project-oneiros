## 0. 要点

- **一个引擎，所有实验都是配置。** 不同的臂只在配置上不同，代码里不出现按臂名的分支。
- **ECS 结构：** 实体是槽位，组件是按槽位排列的数组，系统是纯函数 `state → state`。
- **世界：** 连续的二维平面，加上若干模拟场（温度、气味、光照，后期加入声音）。
- **只有一种生命体，规则对所有个体相同。**
  - 生命体用前后加速度和转向角速度运动，所有输出同时生效。
  - 交互有咬、拿起、放下三种，作用对象可以是任何实体。
  - 吃什么有收益，由食性基因和食物的营养组成共同决定（第 5.1 节）。
- **演化在世界内部发生。** 多个世界并行，每个世界是一个独立的演化种子；个体在世界里繁殖和死亡，没有外层的适应度。
- **观测与干预。** 观测是只读投影，不消耗世界的随机数；干预只在快照分叉里进行。
- **确定性。** 同一配置、同一种子、同一份代码，结果逐位相同。

## 1. 目标与非目标

**目标**

1. 用同一个世界支撑 `PRINCIPLES.md` 第 7 节的所有阶段；进入下一阶段只需要改配置、打开新组件。
2. 所有实验共用一套日志格式、一个分析库和一条预注册流程。
3. 在单张 24 GB GPU 上，同时跑几十个世界、每个世界几百个个体，并演化上千代。

**非目标**

- 实时可视化。需要时从日志离线回放。
- 语言、LLM，以及任何对外的输入输出。
- 以分数为目标的外层优化（ES、GA）。

## 2. 技术选型

**主选 JAX，理由如下：**

- **状态是纯函数的 pytree。** 快照就是把它存下来，分叉就是复制一份，回放就是重跑。
- **随机数由显式的 key 控制。** 每个系统的 key 由 `fold_in(fold_in(world_key, tick), SYSTEM_ID)` 派生。观测器拿不到 key，所以观测开或关，世界的随机数流都不变。
- **并行与编译。** 用 `vmap` 跨世界并行，用 `lax.scan` 把 K 个 tick 编译成一段。
- **有先例。** EvoJAX（Tang et al. 2022）和 Craftax（Matthews et al. 2024）都在单卡上并行运行大量环境。

**确定性**

- 开启 XLA 的确定性选项（例如 `--xla_gpu_deterministic_ops=true`，具体名称以所用版本为准）。
- 场的沉积、接触力的累加这类可能多写一处的操作，用定点整数（int32，固定缩放）累加，结果与顺序无关。
- 成对计算（碰撞、视线）写成稠密的成对数组，再沿固定的轴归约。
- 连续量显式 float32，索引、计数与 uid 显式 int32；x64 关闭（§3.1 的 uid 上限由此而来）。
- **确定性的口径。** 生产口径是 jit + `lax.scan`（`run.segment_ticks`，§3.3）；"逐位相同"只要求同一口径内成立。eager 只是参考实现，跨执行模式（eager vs jit、不同世界批大小）允许 float32 末位差异；运行记录必须写明提交、后端、jax/jaxlib 版本、XLA 标志与批大小（§7.2 runs 表），fork 与续跑在同一口径下进行。

**备选 PyTorch。** 开启 `torch.use_deterministic_algorithms(True)`；系统同样写成纯函数风格；随机数同样按"系统 × tick"派生。

**依赖：** jax、flax.struct（或 chex）、numpy、pyarrow（Parquet）、zarr（轨迹）、tomli（配置）。

## 3. ECS 结构

### 3.1 实体、槽位与引用

| 原型 | 槽位上限（初值） | 说明 |
|---|---|---|
| Creature 生命体 | `N_max` = 256 | 唯一会演化的实体 |
| Bush 灌木 | 60 | 静止不动，结浆果 |
| Carcass 尸体 | 64 | 生命体死后生成，会腐败 |
| Neutral 中性物体 | 3 | 由脚本控制，用作对照刺激 |

- **实体就是槽位下标。** `alive` 掩码表示槽位是否被占用。
- **uid。** 每个实体有全局唯一的 `uid`（int32；x64 关闭，每个世界的计数器远低于 2^31），由世界计数器分配，永不复用。计数器进入 2^31 − 10^6 的余量区时必须报错停止，不得回绕。槽位可以复用，uid 不可以。
- **引用。** 引用写成 `(原型 id, 槽位, uid)`，用于"手里拿着什么""被谁拿着"等。读取时核对 uid；如果不一致，说明槽位已被复用，引用作废，按"已放下"处理。
- **出生。** 按顺序分配空闲槽位，一次写入全部组件，`uid = counter + rank`。
- **死亡。** 把 `alive` 置为 False。下次占用这个槽位时，所有组件被整体覆盖。

### 3.2 组件

| 组件 | 字段 | 适用原型 |
|---|---|---|
| Identity | `uid`、`parent_uid`、`lineage_id`、`generation`、`birth_tick` | Creature（其他原型只有 `uid`） |
| Transform | `pos[2]`（连续坐标）、`θ`、`v`（沿朝向的速度，可为负）、`ω`（上一 tick 的角速度） | Creature、Carcass、Neutral、Bush（灌木静止，速度与角速度恒为 0） |
| Shape | `radius`、`mass` | 全部 |
| Look | `rgb[3]`、`odor[C_o]` | 全部（墙没有气味） |
| Body | `G[3]`（胃内容物）、`N[3]`（营养储量）、`B[3]`（身体组织）、`I`、`X`（毒素负荷）、`b`（核心体温）、`k`、`p`（档位的滞后量）、`φ_hb`（心跳相位）、`S`（困倦压力）、`asleep`、`age`、`μ`（成熟度） | Creature |
| Pain | `a_inj`（急性痛强度）、`x[9, 2]`（各噪声源载波的 AR(2) 状态） | Creature |
| Grip | `holding` 引用、`held_by` 引用 | Creature 两个字段都有；Carcass、Neutral 只有 `held_by` |
| Contact | `touch[4]`（前、右、后、左四个象限上一 tick 的接触力；其中"接触力"定义为碰撞求解前的初始穿透深度，含撞墙越界深度） | Creature |
| Edible | Bush：`stock`（浆果质量）、`kind`；Carcass：`n[3]`、`age_dead` | Bush、Carcass |
| Genome | `g[G]` | Creature |
| Brain | `h[H]`、`s_hat[D]`、`w_fast[P]`、`e[D]`（think 算出的 e_t）、`h_prev[H]`（h_{t−1}） | Creature |
| Motor | `last_out[6]`（意图输出）、`u_eff[2]`（加噪并裁剪后的有效前后加速度与转向角速度） | Creature |
| Scripted | 游走策略的状态 | Neutral |
| Focal | `trace_slot` | Creature，只供观测用，智能体不可见 |

活的生命体也可以被吃，它的可食内容就是 `B + N + G`，不另设组件。

**全局资源：**
- 场（4.3 节）；
- 各种浆果当前的营养组成 `comp[F, 3]`；
- 痛觉束载荷 `w_pain[9, 4]`，每次运行生成一次；
- 时钟 `tick`、uid 计数器；
- 世界边界（矩形墙）；
- 营养账本草稿 `Ledger`：每 tick 由 step 清零，各系统在流动发生处累加流入、流出与内部转移（§3.5）。它是记账与观测的基础设施，智能体不可见。

### 3.3 系统与调度

每个 tick 按固定顺序执行：

```
 1 fields       温度、光照（解析式）；气味场扩散、衰减、沉积
 2 environment  浆果再生；尸体腐败；按时间表重新分配浆果毒素含量；中性物体游走
 3 sense        生成痛觉束与心跳信号；组装每个生命体的切片 s_t（睡眠中视野关闭）
 4 think        大脑前向计算：输出 6 维控制量与内部动作，并给出 ŝ_{t+1}；有意回想（跳到深度 d，取回邻域并按强度加权）
                睡眠中：哨兵处理当前切片，顺序回放切片队列，生成记忆片段（ARCHITECTURES 3.4）
 5 learn        e_t = s_t − ŝ_t；预测权重做 delta 更新；调制 Hebbian 更新
 6 motion       加入运动噪声；积分速度、朝向、位置；被拿着的实体跟随持有者（睡眠中身体输出无效）
 7 collide      解决重叠与撞墙；记录各象限的接触力
 8 interact     依次结算：放下 → 拿起 → 咬（按 5.4 节的判定表）
 9 body         消化与吸收；代谢扣减与营养缺乏；毒素伤害；产热与体温；生长；衰老；档位滞后量与心跳相位；急性痛强度；困倦压力 S；睡眠中的突触巩固
10 reproduce    分裂，子代放在亲代身后的空位
11 die          判定死亡；生成尸体；释放持有物和被持有者
12 events       组装本 tick 的定长、带掩码事件缓冲；它与同 tick 的账本草稿一起作为 lax.scan 的逐 tick 输出交给主机（不写入世界状态）
```

- 每个系统是否启用、参数取什么值，都由配置决定；执行顺序固定。
- 每 K 个 tick 由 `lax.scan` 编译成一段（K = `run.segment_ticks`）；多个世界用 `vmap` 并行。每段结束后，由主机把事件缓冲和轨迹写入磁盘。
- **K 与批大小只影响吞吐。** 结果必须与 K 无关（§13 `test_segment_length`）；单个世界与放进批里的同一世界也必须逐位相同（`test_batch_invariance`）；若某次实测不成立，把批大小写进复现口径（§2、§7.2）。

### 3.4 冲突与优先级

- 每个 tick，用 interact 系统的 key 生成一个随机的优先级排列。
- 多个个体同时拿同一个目标时，优先级最高的成功，其他的记为失败事件。
- 多个个体同时咬同一个目标时，按优先级依次结算，后面的只能从剩下的部分里取。
- 同一个体的多个输出按"放下 → 拿起 → 咬"的顺序结算。

### 3.5 守恒记账

按三类营养分别记账。

- **存量：** 所有生命体的 `G + N + B`、所有尸体的 `n`。
- **流入：** 从灌木咬下的浆果，按咬下那一刻该种浆果的组成计入。灌木上的浆果质量另记一本账：再生量 = 被咬走的量 + 库存变化。
- **流出：** 代谢扣减；未被吸收的部分（植物质和动物质排出，毒素转为毒素负荷后离开营养账）；储量溢出；出生损耗；尸体分解；死亡时没有进入尸体的那部分储量。
- **内部转移：** 尸体腐败时，植物质和动物质转化为毒素；消化时，营养从 G 转入 N。两者都单独记录。

**账本实现（不进入智能体）。** `WorldState` 里有一个每 tick 清零的 `Ledger` 草稿区：

- 流入分类：咬灌木（`bites`）、重播种注入（`reseed`）；
- 流出分类：代谢（`metabolism`）、排出（`excretion`）、溢出（`overflow`）、毒素转入负荷 X（`toxin_load`）、出生损耗（`birth_loss`）、死亡损耗（`death_loss`）、分解（`decomposition`）；
- 内部转移：尸体腐败的植物质/动物质 → 毒素记在 `transfer_from`/`transfer_to`；消化 G → N 记 `digested`（同类守恒，仅作诊断）。

每段结束时用账本总量检查 `流入 = 流出 + Δ存量`，每类营养的相对误差 < 1e-5；内部转移另查 `Σtransfer_from = Σtransfer_to`。账本随 step 作为 scan 输出交出，主机用 float64 累加，不在状态里跨 tick 累计。

## 4. 世界

### 4.1 空间

| 项 | 初值 |
|---|---|
| 平面 | 64 × 64 单位的连续空间，四周有墙 |
| 时间步 | 1 tick |
| 场的网格 | 每单位一格，共 64 × 64 |

### 4.2 实体

| 实体 | 半径 | 质量 | 颜色 | 气味谱 | 行为 |
|---|---|---|---|---|---|
| 成体生命体 | 0.5 | 1.0 | 由基因组决定（3 维，经 sigmoid） | 由基因组决定（C_o 维） | 由大脑控制 |
| 幼体 | 0.5·√m | m 在 0.3–1.0 之间，随生长增加 | 同上 | 同上 | 由大脑控制 |
| 灌木 | 1.0 | ∞（不能被拿起） | 绿色与浆果色按库存比例混合 | 种类谱 × 库存比例 | 静止 |
| 尸体 | 同死者 | 同死者 | 死者颜色 × 0.4 | 腐败谱 × 腐败程度 | 不动，除非被拿着 |
| 中性物体 | 0.4 | 0.2 | 鲜艳，每个物体随机 | 固定的中性谱 | 随机游走，不与任何东西互动 |

**灌木与浆果**

- 灌木共 F = 3 种，每种 20 丛。每丛按种子生成位置，概率正比于 `exp(−(T_geo − T_pref)² / 2σ_T²)`。三种灌木的 T_pref 初值依次为 −1.5、0、1.2，σ_T = 0.5。冷带的浆果要提高档位保暖才能去吃，热带的只能短暂进去取。
- 浆果库存 `stock` 的范围是 [0, 1]，按 `stock += (r·stock·(1 − stock) + 1e-4) × m` 再生：浆果再生率 r 与坚果倍率 m 都是 M1 标定量。**目标值：r=0.09，浆果 m=1，坚果 m=3（坚果实际再生 0.27）。**
- 被咬时，咬下的质量按该种浆果当前的组成，拆成三类营养。
- 基础组成 `(植物质, 动物质, 毒素)` 的初值：
  - 种类 1：(0.85, 0.15, 0)；
  - 种类 2：(0.75, 0.25, 0)；
  - 种类 3（坚果）：(0.6, 0.4, 0)。
- 灌木的颜色是 `绿 × (1 − stock) + 浆果色 × stock`：浆果越多，越能看到浆果的颜色。
- **生命体与灌木的关系：**
  - 生命体可以穿过灌木，两者不碰撞。
  - 从外面看，灌木挡住视线，看不到里面的个体。
  - 个体在灌木里时，自己的视线忽略所在的这丛灌木。
  - 灌木内部遮荫：降温 0.5，光照减半。
- **模糊浆果（第 3 阶段起）。** 加入第 4 种灌木，颜色和气味取两种已有浆果的平均。每次被咬时，有 50% 的概率按有毒的组成结算。

**尸体**

- 死亡时，尸体的营养 `n = B + 0.5·N + G`；另一半储量记为损耗。
- 腐败：每 tick 有 0.5% 的植物质和动物质转化为毒素。腐败程度 `rot = 1 − 0.995^age_dead`，决定腐败气味的强度。
- 尸体超过 600 tick，或营养耗尽，就被移除；剩下的营养记为分解。

**承载量自检**

- 粗估：每丛灌木的最大再生速度约为 `0.03 / 4 ≈ 0.0075`。60 丛约为 0.45 质量/tick。按平均吸收率约 0.6、个体平均消耗约 0.003/tick 计算，承载量 K 约为 90。
- 目标是让 K 落在 `N_max` 的 40–60%。在 M1 标定再生率和灌木数量。
- **M1 目标世界（2026-11-07 冻结）：** base_metabolism=0.0012（0.6×），bush_regen_rate=0.09，坚果再生倍率 3（坚果 0.27），60 丛，N_max=256。用会觅食的 v3 探针测得的 K≈72（验收区间 70–80）。K 更高时限制繁殖的是出生位置（no_room）而不是食物（探针会停在满库存灌木旁），因此不把 K 目标定在 100–150；N_max 保持不变。

### 4.3 模拟场

所有场实现统一的接口：`update(state, key) → state` 和 `sample(field, points) → values`。新增一个场，只需在注册表里加一项，切片布局随配置自动生成。

| 场 | 通道 | 更新方式 | 采样方式 |
|---|---|---|---|
| 温度 T | 1 | 解析式：`T = T_geo(y) + 0.5·cos(2πt/T_day) − 0.5·[在灌木内]`，其中 `T_geo(y) = −2 + 4·y/64` | 用于皮肤温差 `T − b`，取身体中心的值 |
| 光照 E | 1 | 解析式：`E = (0.5 + 0.5·cos(2πt/T_day))·(1 − 0.5·[在灌木内])` | 取身体中心的值；同时决定视野的亮度和噪声（符号改用 E，L 专指寿命） |
| 气味 O | C_o = 4 | 网格：`c ← (1 − δ)·diffuse(c) + 沉积`，扩散核 3×3，D = 0.2，δ = 0.02；用定点整数累加沉积 | 一个鼻子，位于正前方、距中心 r + 0.2 处，用双线性插值读取 |
| 声音 S（第 6 阶段） | S = 2 | 不存网格，逐对计算：幅度为 `max(0, u_snd)`，接收量为 `Σ 幅度 · exp(−d/4)`，只计 d < 10 的声源 | 两只耳朵分别位于 θ ± 90° |

- **气味源：** 灌木（种类谱 × 库存比例）、生命体（由基因组决定）、尸体（腐败谱 × rot）、中性物体（固定谱）。
- **毒素没有专属的气味或颜色。** 浆果的外观和气味只取决于种类，不取决于当前含毒多少。所以哪种浆果有毒，只能从后果中学到。
- **可选的风场：** 按风向平移气味场，风向随季节缓慢旋转。默认关闭。

### 4.4 浆果毒素含量的切换

- 每隔 `T_switch = c_switch · L`（`tick % round(T_switch) == 0`，含 tick 0），用 environment 系统的 key 随机选出一种浆果作为"含毒"种类。它的组成变为 `(1 − 0.4·α) × 基础组成 + 0.4·α × (0, 0, 1)`，其余种类恢复为基础组成。c_switch 是实验因子，取值为 {0.25, 0.5, 1, 2, 4}。
- **α 是爬坡强度。** 爬坡期 α 从 0.1 线性升到 1（`core/ramp.toxin_strength`，§9），爬坡结束后 α=1；切换时间表在爬坡期照常运行。早期的理由是：若把毒素清零，`ρ_T > 0` 的所有个体都会慢性缺毒素类营养（2026-11-06 复核问题 7）。
- 对不耐毒的个体来说，这种浆果是有害的；对以毒为食的个体来说，它反而成了食物。同一次切换，对不同基因型的意义正好相反。

### 4.5 中性物体

- 颜色鲜艳，有固定的气味，随机游走。
- 可以被拿起；可食内容为空，所以咬它没有任何效果。
- 用作判据 E1 的对照刺激：它带来的感官变化同样大，但与存活无关。

## 5. 生命体

### 5.1 营养与食性

**这是全部进食规则，对所有个体相同。** 捕食、食腐、同类相食、以毒为食，都只是它可能产生的结果，不另设规则。

```
营养类型 j ∈ {P 植物质, A 动物质, T 毒素}

食性基因：ρ = softmax(基因组中的 3 个 logit)        需求比重，ρ_P + ρ_A + ρ_T = 1
储量上限：N_cap,j = ρ_j
转换率：  ε_j = 0.9 · ρ_j^γ，γ = 0.5                  γ 是世界参数：γ < 1 偏向杂食，γ > 1 偏向专食

咬下一口：从目标的可食内容 n 中按比例取走 q，得到 Δn = q · n / |n|₁
  q 受胃的剩余容量限制：q ≤ G_cap − |G|₁，G_cap = 0.3；取不下的部分留在目标里
  入胃：  G += Δn

消化（每 tick）：Δ = r_dig · G，r_dig = 0.05（平均停留约 20 tick）；G −= Δ
  吸收：  N_j += ε_j · Δ_j，超出上限 N_cap,j 的部分记为溢出
  排出：  未被吸收的 P、A 排出（记为损耗）
  中毒：  未被吸收的 T 转为毒素负荷，X += κ_tox · (1 − ε_T) · Δ_T，κ_tox = 3

代谢：每 tick 的需求 c_tot（见 5.3）按 ρ 分摊：N_j −= ρ_j · c_tot
缺乏：某类储量不足时，差额 d_j 由身体承担：I −= 5 · Σ_j d_j
毒素：每 tick I −= 0.01 · X，然后 X *= 0.95，所以伤害是延迟出现的
```

**可食内容 n 的定义**

| 目标 | n |
|---|---|
| 灌木 | `stock × 该种浆果当前的组成` |
| 尸体 | 自身的 `n` |
| 活的生命体 | 它的 `B + N + G`；被咬时，三者按比例减少 |
| 中性物体 | 空 |

**消化带来的延迟**

- **收益延迟：** 咬下的东西要在胃里停留，大约 20 tick 内才逐步进入储量。学习必须跨越"吃下去"和"储量上升"之间的这段时间。
- **伤害延迟两层：** 毒素先要被消化才变成毒素负荷，毒素负荷又要再过一段时间才伤害身体。
- **胃满就咬不下：** 胃里装了什么，决定了接下来还能吃什么。这让营养的平衡成为一个真实的取舍。胃装到八成以上会胀痛（5.6）。
- **快慢两个信号：** 胃的充盈是快信号，饥饿痛是慢信号，两者分别进入内感受，不合并。"胃饱但缺某类营养"或"胃空但储量还足"都可能出现，这为"饱"和"缺"分化成不同的内部状态提供了条件。
- **可选：`digestion.knob_coupling`（默认关闭）。** 打开后，`r_dig × (1 − 0.5·k)`，即高档位时消化变慢。这是人为加上的身体耦合，打开它需要单独做检验。

**身体组织 B 的组成固定为 `c_flesh = (0.3, 0.7, 0)`。** 由于活体的可食内容包含储量 N，以毒为食的个体体内带有毒素，不耐毒的个体去吃它就会中毒。活体组织还带有草食性防御毒素：咬下的活体质量转为咬者的毒素负荷，不提供营养（§5.4）。警戒色和拟态因此有了产生的条件，但这只是一个可能的结果。

**创始个体的食性：** 植物质 logit 取自 N(0, 1)，动物质 logit 取自 N(−1, 1)（M1 起默认；2026-11-07 复核：N(0,1) 会让大多创始个体靠浆果拿不够动物营养），毒素的 logit 取自 N(−3, 1)。所以一开始大多数个体不耐毒。这是一项创始条件，之后由演化改变。

**可选：`diet.decoupled: true`。** 转换率改由另一组独立的基因 ψ 决定，即 `ε_j = 0.9·ψ_j^γ`；需求仍然由 ρ 决定。这样"耐毒但不需要毒"（只解毒、不当营养）也成为可能。

### 5.2 身体状态

| 量 | 范围 | 规则 |
|---|---|---|
| 胃内容物 G | \|G\|₁ ≤ G_cap = 0.3 | 见 5.1；出生时为空；充盈程度直接可读，装到八成以上引起胀痛 |
| 营养储量 N | 每类在 [0, ρ_j] 之间 | 见 5.1；不可读，只通过饥饿痛被感到 |
| 身体组织 B | 向量 | 生长时由 N 按 c_flesh 的比例转入 |
| 完整度 I | [0, 1] | 归零即死。Σ N > 0.5 时，每 tick 恢复 0.002，这份消耗按 ρ 的比例计入当 tick 的需求。不可读，只能从控制误差推断（5.3）；被咬时引起急性痛 |
| 毒素负荷 X | ≥ 0 | 见 5.1；不可读，只通过毒痛被感到 |
| 核心体温 b | 实数 | `b ← b + 0.05·(T − b) + 0.06·k²`；当 \|b\| > 1 时，`I −= 0.002·(\|b\| − 1)`。不可读，只通过冷热不适被感到 |
| 档位 k | [0, 1] | 由大脑输出 |
| 档位滞后量 p 与心跳相位 φ_hb | p ∈ [0, 1] | `p ← 0.9·p + 0.1·k`；`φ_hb ← φ_hb + 2π·(1 + 2p)/20`，心跳周期从 20 tick 缩短到约 6.7 tick |
| 质量 m 与成熟度 μ | m 在 [0.3, 1]；`μ = (m − 0.3) / 0.7` | 生长：每 tick 最多增加 `0.7 / a_mature`（a_mature = 100）的质量，同时从 N 中按 c_flesh 的比例转出 `0.1·Δm` 到 B。营养不够时，这一 tick 就不生长 |
| 年龄 a | 以 tick 计 | a > a_sen = 400 之后，代谢加成为 `(a − a_sen) / a_sen` |
| 困倦压力 S | [0, 1] | 清醒时随时长和回想步数上升，睡眠中下降（ARCHITECTURES 3.1）。不可读，只通过困倦噪声被感到；S 越大，隐单元的噪声越大 |
| 睡眠 asleep | 布尔 | 由内部动作进入和退出。睡眠中：身体输出无效，档位为 0，视野关闭，基础代谢减半，不写入切片队列；被咬、中毒、体温照常发生（ARCHITECTURES 3.2–3.3） |

- 档位为 0 时，体温会跟随环境温度；档位越高，产热越多。所以在冷的地方提高档位可以保暖，在热的地方奔逃则会过热。
- 成熟要靠营养：吃不到足够的动物质，幼体就长不大。

### 5.3 运动与输出

大脑每个 tick 输出 6 个量，它们同时生效：

| 输出 | 范围 | 含义 |
|---|---|---|
| `u_acc` | [−1, 1] | 前后加速度 |
| `u_turn` | [−1, 1] | 转向角速度，左为负、右为正 |
| `k` | [0, 1] | 代谢档位 |
| `u_bite` | [−1, 1] | 大于 0 时咬，力度 `s = u_bite` |
| `u_grab` | [−1, 1] | 大于 0 时尝试拿起 |
| `u_drop` | [−1, 1] | 大于 0 时放下 |

第 6 阶段追加 `u_snd[S]`。

```
u'     = clip(u + N(0, σ_m²), −1, 1)，σ_m = 0.05·(1 + 2·(1 − I))   运动噪声，受伤后变大
c_I    = 0.3 + 0.7·I                                            完整度对身体的削弱
g      = (0.3 + 0.7·μ)·c_I                                      身体效能（altricial 模式下前一项为 0.05 + 0.95·μ）
a_max  = 0.05·(1 + k)·g / (1 + m_held / m)
v      ← (v + a_max·u'_acc)·(1 − 0.1)，再裁剪到 |v| ≤ 0.5·(1 + 0.5k)
θ      ← θ + 0.3·c_I·u'_turn                                     单位：弧度/tick
pos    ← pos + v·(cos θ, sin θ)
```

- **有效控制 u'。** 加噪并裁剪后的前后加速度与转向角速度记作 u'，由 motion 写入 `Motor.u_eff`；代谢计费与交互判定读它，不再各自重推导噪声。
- **非线性。** 加速度要经过速度积分，还要扣掉阻力，所以输出与效果之间不是线性关系，也不是即时生效的。
- **受伤只能从控制误差中察觉。** 完整度不进入切片。它通过 c_I 和 σ_m 削弱推进、转向、咬和握，并放大运动噪声。传出副本记录了"想做的"，本体感觉和触觉记录了"做到的"，两者之间的差异，就是系统能得到的全部受伤信息。g 同时用于 5.4 节的咬与握。
- **碰撞。**
  - 积分之后，把互相重叠的实体沿法线方向、按质量比例推开：规格下限是 2 次迭代，之后继续迭代直到最大残余重叠 < 1e-3，上限 12 次；达到上限时计数，供观测与验收使用。
  - 不参与碰撞的：被拿着的实体；生命体与灌木之间。
  - 撞墙时，位置裁剪回边界内，速度减半。
  - 接触力定义为碰撞求解前的初始穿透深度（含撞墙越界深度）。按接触点方向相对朝向的夹角分到前、右、后、左四个象限（右转为正），作为下一 tick 的触觉输入。

**每 tick 的代谢需求：** 所有动作代价共用一个能量尺度 `base_metabolism`（默认 0.002，M1 标定）：加速项系数 = base，转向项 = 0.25·base，咬项 = base；基础项再乘 `m^0.75`（幼体质量 0.3 时为基础项的约 41%，成体 m=1 不变——这是身体物理尺度，不是行为设计）。

```
b = body.base_metabolism
c_tot = b·(1 + 3k²)·(1 + 衰老加成)·(睡眠时 × 0.5)·m^0.75
      + b·|u'_acc|·(1 + k)·(m + m_held)
      + 0.25·b·|u'_turn|
      + b·max(0, u_bite)
      + 修复完整度的消耗（仅当 I < 1 且 ΣN > 0.5 时修复；修复量 = min(0.002, 1 − I)，只计实际修复量）
      + 记忆与回想的代价（ARCHITECTURES 2.4）
```

### 5.4 交互与判定表

**交互范围：** 目标中心在前方 ±30° 以内，并且距离 `d ≤ r_self + r_target + 0.2`。身处灌木内部时，也可以咬这丛灌木。

- **拿起：** 在范围内可以被拿起的实体中，选最近的一个。
- **咬：** 在范围内的所有实体中，选最近的一个。手里拿着的东西就在正前方，所以咬到的通常就是它。

| 动作 \ 目标 | 灌木 | 尸体 | 活的生命体 | 中性物体 |
|---|---|---|---|---|
| **咬**（力度 s） | `q = min(stock, 0.05·s·(1+k)·g)`，按 5.1 节结算 | `q = min(\|n\|₁, 0.05·s·(1+k)·g)`，按 5.1 节结算 | 对方 `I −= 0.1·s·(1+k)·g`；`q = min(0.5·\|B+N+G\|₁, 0.03·s·(1+k)·g)`，按 5.1 节结算 | 内容为空，没有效果 |
| **拿起** | 不可以 | 质量不超过 0.5·m 时成功 | 对方质量不超过 0.5·m，且这一 tick 没有挣脱，则成功 | 成功 |
| **放下** | — | 放到正前方，如有重叠，由下一 tick 的碰撞推开 | 同左；对方随即恢复运动能力 | 同左 |

- **胃容量限制。** 表中所有的 q，都还要受咬者胃的剩余容量限制。咬活体造成的伤害不受这个限制。
- **一次只能拿一件东西。** 被拿着的实体位于持有者正前方的接触距离处，随持有者移动。
- **被拿着的活体：**
  - 自己的推进不起作用；
  - 每个 tick 判定一次能否挣脱：如果 `|u'_acc|·a_max(被拿者) > 0.03·(1 + k_持有者)·g_持有者`，就挣脱，并记录事件；
  - 可以咬持有者。
- **视线：** 持有者自己的视线忽略手里的东西；其他个体能看见它。
- **睡着的个体同样是交互对象：** 可以被咬、被拿起；它自己的输出无效。
- **判定表只规定物理后果。** 它不区分进食和攻击，也不区分同类和异类。咬一个活体有没有营养收益，完全取决于 5.1 节的规则。
- **活体防御毒素（2026-11-07 用户裁决）：** 咬活体时，被咬下的质量不进入胃，而是按 `world.live_bite_toxin`（目标值 1.0）转为咬者的毒素负荷 X，并记为 `OUTFLOW_TOXIN_LOAD`；尸体仍按正常食物处理。攻击行为保留，但啃食活体没有营养收益、并产生毒性。

### 5.5 繁殖与死亡

- **繁殖条件：** `Σ N ≥ θ_repro`（来自基因组，裁剪到 [0.5, 1]），且 μ = 1。满足时自动分裂，不需要专门的动作。
  - **位置：** 子代放在亲代身后，距离为 r_亲 + r_子。如果被占，依次尝试 ±45°、±90°、±135°。都被占时，出生失败，记录事件。
  - **亲代的支付：**
    - **先从亲代储量 N 中按 c_flesh 的比例支付子代的身体组织** `B_child = 0.03·c_flesh`（与 §5.2 生长同一规则；成体的 B 不再被繁殖消耗）。任一类储量不够时，出生失败，原因记 `no_reserve`。
    - 再按 `0.3·ρ_子` 从剩余 N 中支付子代的初始储量，哪一类不够就少给。
    - （2026-11-06 澄清：原表述没有写清从 B 还是 N 支付，实现方按 B 支付，导致一生最多繁殖 3 次。现按本条执行；`reproduction.tissue_from_reserves = false` 仅保留为 A/B 对照。）
    - 另外按自身 ρ 的比例支付 0.02 的出生损耗。
  - **子代：** 质量 0.3；胃为空；朝向用 reproduce 系统的 key 随机决定；基因组按 6.3 节变异；隐状态和可塑权重从零开始。对照臂 `reproduction.randomize_genome = true` 时，子代基因组改为全新随机抽样（§6.3 的初始化表），用来检验遗传的必要性（§9 M1）。
- **出生预算与变异噪声（C5）。** 每个世界每 tick 最多 `B_MAX = 16` 个出生：成熟且达到阈值的亲代按 reproduce key 的随机排列排序，前 B_MAX 个真正分裂，其余本 tick 顺延（不消耗胎次），每个顺延的亲代发一条 `birth_defer` 事件。变异噪声按子代生成，key = `fold_in(reproduce_key, 子代 uid)`，所以一个出生的基因组只取决于 (reproduce_key, 子代 uid)，不依赖同 tick 的其他出生；每 tick 至多 B_MAX × 基因组宽度 份噪声，而不是"容量 × 基因组宽度"。B_MAX 是标定量（初值 16）。
- **亲子依赖（第 5 阶段，`altricial: true`）：** 成熟系数改为 0.05 + 0.95·μ，a_mature 延长到 200。幼体几乎不能移动，咬的力度也很小。亲代会不会把幼体搬到灌木旁或尸体旁，由演化决定。
- **死因（衰减损失归因）：** `Damage.loss[5]` 按来源（营养、毒、热、冷、咬）累计完整度伤害，每 tick 按 50 tick 时间常数指数衰减；完整度归零时，取死亡当 tick 衰减累计最大的来源作为死因（并列时按该顺序取先者）。死亡事件附上整个损失向量；营养类死因再附缺的是哪一类营养。I ≤ 0 的当 tick 即判死，修复不作用于 I ≤ 0 的个体。旧规则“按最后一次伤害的来源记录”作废。原始条目：
  - 营养缺乏（注明缺的是哪一类）；
  - 被咬（注明咬的是否同一谱系）；
  - 毒素；
  - 过热或过冷。
  - 衰老只通过代谢加成起作用；另设兜底上限 `a_max = 5·a_sen`。
- **死亡处理：** 生成尸体；手里的东西放在原地；如果死者正被别人拿着，就从持有者手中释放。
- **灭绝与重播种：** 种群少于 8 个时，用随机基因组重新播种 32 个，并记录重播种的次数。

### 5.6 传感器与切片布局

切片的顺序固定，但智能体不知道每一段是什么。

| 段 | 维度 | 内容 |
|---|---|---|
| 视野 | 1 × 15 × 3 = 45 | 前向 60°，每像素 4°，从左到右排列 |
| 嗅觉 | C_o = 4 | 正前方一个鼻子，读数为 `log(1 + c)`（器官的固定变换）。没有左右之分，浓度梯度只能靠移动和转向时读数的变化来推断 |
| 触觉 | 4 | 前、右、后、左四个象限的接触力 |
| 负重 | 1 | 手里东西的质量，空手时为 0 |
| 本体感觉 | 2 | 当前速度 v；上一 tick 的实际角速度 |
| 内感受 | 6 | 胃的充盈程度 \|G\|₁；痛觉束 4 路（见下）；心跳 1 路 |
| 皮肤温差 | 1 | `T(所在位置) − b`，加噪声。外界比身体热时为正，比身体冷时为负 |
| 光照 | 1 | 所在位置的 E |
| 传出副本 | 6 | 上一 tick 的 6 个输出 |
| 合计 D | 70 | 第 6 阶段追加 2 × S = 4 维声音，合计 74 |

**视野**

```
像素 i（0…14，从左到右）的方向：φ_i = θ − 30° + (i + 0.5)·4°
沿 φ_i 投射一条射线，最远 R_view = 16：
  命中最近的实体圆或墙 → 颜色 c，距离 d
  RGB_i = c · exp(−d/6) · E + N(0, σ_v²)，σ_v = 0.02 + 0.08·(1 − E)
  没有命中 → RGB_i = 0，再加噪声
射线忽略：自己、自己手里的东西、自己所在的那丛灌木
墙的颜色为灰色
```

- 距离只能从亮度衰减和物体占据的像素宽度推断，不另设深度通道。
- 睡眠中视野关闭：全部像素为 0，再加噪声。
- 每类传感器都加独立的高斯噪声，标准差在配置里设定。

**痛觉束**

身体状态都不进入切片，包括营养储量 N、完整度 I、毒素负荷 X、核心体温 b。系统只能通过三条途径感到它们：痛觉束里的噪声、心跳的节律（5.2），以及控制误差（5.3）。

痛觉束是 4 路共用的内感受通道（通道数是内感受束的物理属性，与嗅觉通道数无关）。九个噪声源叠加在里面，每个源的强度来源、波形和周期都不同：

| 噪声源 | 强度 a_k（由身体状态算出，不进入切片） | 波形 | 周期 P_k | 阻尼 r_k |
|---|---|---|---|---|
| 急性痛 | 被咬时：`a_inj ← 0.7·a_inj + 10·ΔI_被咬` | 稀疏脉冲：每 tick 以概率 min(1, a_inj) 出现 ±1 的脉冲，再做 φ = 0.5 的一阶平滑 | 无 | — |
| 毒痛 | `2·X` | 共振噪声 | 5 | 0.90 |
| 胀痛 | `max(0, \|G\|₁/G_cap − 0.8) / 0.2`：装到八成开始痛，装满时为 1 | 共振噪声 | 8 | 0.90 |
| 热不适 | `max(0, b − 0.5)` | 共振噪声 | 12 | 0.95 |
| 冷不适 | `max(0, −b − 0.5)` | 共振噪声 | 20 | 0.95 |
| 饥饿痛·植物质 | `min(1, 3·ρ_P)·(1 − f_P)²` | 共振噪声（慢波） | 40 | 0.995 |
| 饥饿痛·动物质 | `min(1, 3·ρ_A)·(1 − f_A)²` | 同上 | 70 | 0.995 |
| 饥饿痛·毒素 | `min(1, 3·ρ_T)·(1 − f_T)²` | 同上 | 110 | 0.995 |
| 困倦 | 困倦压力 S | 共振噪声 | 30 | 0.97 |

其中 `f_j = N_j / N_cap,j` 是各类储量的充满程度。

```
共振噪声 AR(2)：x_k(t) = φ1·x_k(t−1) + φ2·x_k(t−2) + c_k·ξ_k(t)
  φ1 = 2·r_k·cos(2π / P_k)，φ2 = −r_k²
  c_k = sqrt( (1 + φ2)·((1 − φ2)² − φ1²) / (1 − φ2) )      保证 x_k 的稳态方差为 1
痛觉束：y(t) = Σ_k a_k(t)·x_k(t)·w_k + 0.02·ξ_0(t)        y ∈ R^4
  w_k 是单位向量，每次运行由种子生成一次，所有个体共用
  所有 ξ 都由 sense 系统的 key 生成
```

- **只有组成和分布带信息。** 每个源的均值都是 0，单个读数几乎说明不了什么。是哪种不适、有多强，只能从一段时间内的波形、周期，以及它在 4 路之间的分布来分辨。九个源挤在 4 路里，单靠"在哪一路"分不开，必须靠时间结构。
- **阻尼的取法。** 周期越长，阻尼要越接近 1，峰才够尖：谱峰的半高宽约为 (1 − r)/π（单位：周期/tick）。r = 0.98 时，周期 110 那个峰的相对带宽约为 0.7，和周期 70 的峰大面积重叠；取 0.995 时降到约 0.2。
- **强度越大，噪声越大。** 毒性越强、吃得越撑、体温偏得越远、缺得越多、伤得越重，对应的那个源就越吵。
- **不适先于伤害。** |b| > 0.5 时就开始产生冷热不适，但要到 |b| > 1 才开始造成伤害。这个阈值是传感器的物理性质，不是行为规则。
- **疼痛就是去不掉的预测误差。** 噪声的细节无法预测，周期结构也只能部分预测。所以在有预测单元的臂里，痛觉束上的误差能量会随强度增大：疼痛表现为持续的、消除不掉的误差，但它不是设计者给出的"疼痛值"。
- **很少需要的营养不会一直痛。** 饥饿痛的系数 `min(1, 3·ρ_j)` 保证了这一点：几乎不需要毒素的个体，"毒素饥饿"那个源是安静的。
- **皮肤温差与适应。** 档位为 0 时，体温会趋向环境温度，温差随之回落到 0。所以温差信号会自然地适应，只在进入冷热不同的地方、或改变档位时明显。档位高时体温高于环境，温差为负，感到的是散热。环境的绝对温度不可读。
- **心跳。** 心跳通道为 `sin(φ_hb) + 0.05·ξ`，档位只能从心跳的快慢中感到。
- **可选：`pain.mode`。**
  - `bundle`：默认。
  - `separate`：每个源独占一路，共 9 路，载荷取单位阵，D 变为 75。只在需要排除"分不开"这个因素时使用。
  - `neural`：不设专用通道，把 Σ_k a_k·x_k 直接加到隐单元的输入上。

**对照臂对切片的改动**

- **`readable` 臂（`leak: true`）：** 在切片末尾追加 5 维设计者摘要：
  1. `Σ N − 0.5`；
  2. 完整度 I；
  3. 毒素负荷 X；
  4. 核心体温 b；
  5. 半径 3 以内是否有在过去 50 tick 里咬伤过活体的个体（用真实值；记录的是咬人者一方，需要一个独立的每体 `last_live_bite_tick` 组件，所有臂都由 interact 写入）。
  - 该臂暂缓到 M3 第 3 阶段；在此之前配置校验直接拒绝 `learning.readable_leak=true`（不再等到 trace 时才失败）。
- **`no_body_loop` 臂：**
  - 心跳固定为静息频率（周期 20 tick）；
  - 传出副本里去掉档位；
  - 体温方程中的产热项改为常数 `0.06·k̄²`，k̄ 取自标定记录。
  - 这样做也改变了热的物理，所以比较与热应激有关的结果时要谨慎。

## 6. 大脑

### 6.1 默认大脑：调制可塑的循环网络

**前向计算：**

```
输入：s_t (D)，e_t = s_t − ŝ_t (D)，h_{t−1} (H)

h_t      = tanh( W_in·s_t + W_err·e_t + W_rec·h_{t−1} + b + σ_n·S·ξ )     σ_n = 0.3：越困，噪声越大
out_t    = [ tanh(W_out·h_t + b_out)   5 维：u_acc、u_turn、u_bite、u_grab、u_drop
             sigmoid(w_k·h_t + b_k) ]  1 维：k
m_t      = tanh( W_mod·h_t ) ∈ R^M     M = 4 个调制单元
m̃_j      = Σ_k G[j,k]·m_t[k]           每个突触后单元 j 的调制量
ŝ_{t+1}  = W_pred·h_t

所有权重都由两部分相加：W_* = W_*^slow + W_*^fast
W_slow 的初值取自基因组，清醒时不变；睡眠中巩固：W_slow += ρ_j·W_fast，W_fast ← (1 − ρ_j)·W_fast
```

**学习：**

- **预测权重：** 用局部 delta 规则更新，`W_pred^fast += η_p · e_t ⊗ h_{t−1}`。
- **调制 Hebbian：** 用于 W_in、W_rec、W_out。对每个突触后单元 j：

  ```
  ΔW_ij = η_j · m̃_j · (A_grp·pre_i·post_j + B_grp·pre_i + C_grp·post_j + D_grp) − λ_j · W_ij^fast
  W^fast 裁剪到 [−1, 1]
  ```

- **各组权重的 pre 和 post：**

  | 权重 | pre | post |
  |---|---|---|
  | W_in | s_t | h_t |
  | W_rec | h_{t−1} | h_t |
  | W_out | h_t | out_t |

- **粒度与时机。** 调制量 m̃_j、η_j 与 λ_j 都按突触后单元给出：隐单元 H 个 + 输出单元 N_OUT 个，所以 G 的形状是 (H + N_OUT) × M；A–D 按三组权重（W_in、W_rec、W_out）。Hebbian 的 pre/post 取同一 tick（即上表）：“上一 tick 的 pre/post”是旧写法，作废。

### 6.2 臂（只是配置）

| 臂 | 可塑性 | 预测与误差单元 | η 的粒度 | 泄漏 | 检验 |
|---|---|---|---|---|---|
| `fixed` | 关（η = 0） | 关（W_pred、W_err 置零） | — | 否 | H0 的基线 |
| `hebb` | 开 | 关 | 每单元 | 否 | H0 |
| `hebb_pred` | 开 | 开 | 每单元 | 否 | 主臂：H0、H1、H2 |
| `shared_eta` | 开 | 开 | 每组一个 | 否 | H2 |
| `readable` | 开 | 开 | 每单元 | **是** | H1 |
| `no_body_loop` | 开 | 开 | 每单元 | 否 | H3 |

- 代码里只有能力开关：`plasticity.enabled`、`prediction.enabled`、`eta.granularity`、`body_loop.enabled`。
- **零差异检查：** 打开 `hebb` 的代码路径、但把 η 强制为 0 时，结果必须与 `fixed` 逐位相同。

### 6.3 基因组与变异

**基因组包括：**

- 全部 W^genome 与偏置，以及 W_mod、G（G 的形状是 (H + N_OUT) × M）；
- 每个单元的 η_j、λ_j、ρ_j（以对数存储；ρ_j 是睡眠中的巩固率）；
- 每组权重的 A–D 与 η_p；
- 繁殖阈值 θ_repro；
- 体色（3 维）、气味谱（C_o 维）；
- 食性 logit（3 维；decoupled 模式下另加 3 维 ψ）。

**宽度由布局推出。** 基因组宽度与快权重宽度不是配置项：由 H、D、M 和输出数按上面的块顺序累加得出（共享头见 6.5 节），D 变化时所有数组随之改变。可塑权重只包含 W_in、W_rec、W_out、W_pred 四个矩阵。

**初始化（C4）。** 创始个体按块抽样正态分布，标准差由扇入决定，不预先设计任何接线；这样每个创始个体的默认动作倾向不同：

| 块 | 初始标准差 |
|---|---|
| W_in、W_err | 1/√D |
| W_rec、W_out、W_mod、W_pred | 1/√H |
| G | 1/√M |
| 隐单元偏置 b | 0.1 |
| 输出偏置 b_out | 1.0 |
| log η、log λ、log η_p、hebb A–D | 0.1（中心值待 M2 实测后再定） |
| 共享头（食性/体色/气味/θ_repro） | 0.1，随后按 §5.1 / §5.3 覆盖 |

食性 logit 的初始分布见 5.1 节。

**变异：** `g' = g + σ_block ⊙ N(0, 1)`。噪声按子代取 key（`fold_in(reproduce_key, 子代 uid)`，§5.5），出生结果与同 tick 的其他出生无关。各块 σ 的初值：

| 块 | σ |
|---|---|
| 权重 | 0.02 |
| log η、log λ、log ρ | 0.1 |
| θ_repro | 0.02 |
| 体色、气味谱 | 0.05 |
| 食性 logit | 0.05 |

先做无性繁殖；有性繁殖作为以后的选项。

### 6.4 候选大脑

默认大脑是 6.1 节的调制可塑循环网络，即 `ARCHITECTURES.md` 中的 B0。其他候选都写在 `ARCHITECTURES.md` 里，通过配置项 `brain` 选择：

- `plastic_rnn`：B0；
- `slice_transformer`：B1；
- `queue_rnn`：B2；
- `queue_segment_rnn`：B3；
- `mtrnn`：B4；
- `four_layer`：B5。

所有候选共用同一套身体接口：输入为切片 s_t，输出为 6 维身体控制量和预测 ŝ。所有候选都有内部动作"入睡"与"唤醒"；部分候选另有帧的写入强度、有意回想（是否回想与深度）、事件边界、片段的写入强度，这些输出同样进入传出副本，并按连续量计入代谢需求。

### 6.5 规模估算（默认大脑：H = 32，D = 70，6 个输出）

| 项 | 参数量 |
|---|---|
| W_in、W_err、W_pred | 各 2,240 |
| W_rec | 1,024 |
| W_out 与 w_k | 192 |
| W_mod | 128 |
| G（38 × 4，调制按突触后单元） | 152 |
| 偏置、可塑性参数（η/λ 各 38，A–D 12，η_p 1）、θ_repro、体色、气味谱、食性 | 138 |
| 基因组合计（含共享头 11） | 8354 |
| 可塑权重（W_in、W_rec、W_out、W_pred） | 约 5.7k |

- **内存：** 每个个体约 14k 个 fp32，约 56 KB。64 个世界 × 256 个槽位 = 16,384 个个体，约 1 GB，还有余量把 H 提到 64。
- **主要开销：** 成对碰撞和视野光线投射。每个世界约 380 个实体槽位，成对计算约 14 万对；光线与圆的相交测试约 15 × 256 × 380 ≈ 146 万次。先用稠密实现，在 M0 实测；达不到吞吐目标时，再改成均匀网格分桶的邻居表。
- **吞吐目标：** 单卡每秒至少 5e5 个"个体·tick"，实测后修订。按 16k 个个体算，约 30 tick/s。若 L 约为 500 tick，演化 1000 代约需 4–5 小时。
- **演化太慢时：** 可以在同一臂的世界之间启用迁移（岛屿模型，`migration_rate`），并在配置中记录。

## 7. 观测

### 7.1 原则

- **观测器是纯投影：** `observe(state, events) → record`。它不拿 key，也不返回状态。
- **观测器作为 scan 的输出运行：** 打开或关闭观测器，都不会改变状态轨迹（见第 13 节的测试）。
- **单向依赖：** sandbox 不导入 analysis；analysis 只读日志。

### 7.2 日志表

| 表 | 粒度 | 主要字段 |
|---|---|---|
| `runs` | 每次运行 | run_id、mode（confirmatory/exploratory/intervention）、prereg_id、code_commit、config_hash、种子、起止时间、GPU、最终状态哈希 |
| `events` | 每个事件 | world、tick、type、uid、目标原型、target_uid、是否同一谱系、x、y、取走的 Δn[3]、吸收量[3]、ΔX、伤害、cause、缺哪类营养（nutrient，仅死亡事件）、衰减损失向量（loss[5]，仅死亡事件）、父代 uid（parent_uid，仅 birth 事件；出生失败时 uid 即亲代）、成败与原因。重播种个体也写 birth 事件，reason = reseed。type 包括 birth、birth_fail、death、bite、grab、grab_fail、drop、escape、toxin_switch、reseed、sleep_start、sleep_end（注明自己醒来还是被唤醒、回放是否完成）、recall（深度与读到的帧数） |
| `lives` | 每个个体一行 | uid、parent_uid、lineage_id、generation、出生与死亡 tick、死因、后代数、食性 ρ、一生按来源（灌木各种类、尸体、活体）和按营养类型分的摄入与吸收、被咬次数、咬活体次数、被搬运次数、搬运他物次数、基因组或基因组指针 |
| `world_ts` | 每 k_ts 个 tick | 种群数；出生数；按死因分的死亡数；平均 ΣN；平均 b；浆果总库存；尸体数；食性分布（ρ 的直方图）；食物网计数（各食性区间之间的咬与吸收）；槽位上限是否被触及；性状的均值与方差 |
| `focal_traces` | 焦点个体，每 tick | uid、tick、s (D)、ŝ (D)、h (H)、各单元 \|ΔW^fast\|、m (M)、out (6)、痛觉各源强度 a[9]、G[3]、N[3]、I、X、b、p、v、ω、pos、θ、持有物的原型和 uid、S、asleep、回想深度 d、队列占用与强度分布 |
| `genomes` | 每 k_g 个 tick 抽样 | uid、g |
| `snapshots` | 每 T_snap 个 tick | tick、路径、状态哈希 |
| `forks` | 每次干预 | fork_id、snapshot、patch 规格、配对的对照 fork_id |

事件、个体、时间序列和基因组写成 Parquet；焦点轨迹写成 zarr（float16）。

### 7.3 焦点个体抽样

- 个体出生时，若 `hash(run_seed, uid) < p_focal`，就成为焦点个体。这个判定不使用世界的随机数。
- 每个世界有 `K_focal = 16` 个轨迹槽位，占满后不再加入新的焦点个体。
- 可选：把若干个创始个体的全部后代标为焦点谱系。

### 7.4 快照

- 每隔 T_snap = 20,000 tick，以及每个阶段结束时，把完整状态存成 npz，同时记录 schema 版本、config_hash 和 code_commit。
- 从快照续跑的结果，必须和不间断运行逐位相同。

### 7.5 存储预算

焦点轨迹每行约 240 个数（s 与 ŝ、h、各单元 |ΔW|、m、输出、身体标量），用 float16 存储：

```
每个世界每 tick ≈ 16 × 240 × 2 B ≈ 7.7 KB
```

- 64 个世界跑 1e6 tick，全量约 0.5 TB。
- 默认做法：
  - 每个 L 内只记录 0.05·L 个 tick（约 26 GB）；
  - 在以下事件前后各加 50 tick 的窗口，并设总量上限：被咬、中毒、亲属死亡、毒素切换、被拿起。
  - 这样每次运行约 30–60 GB。
- 快照每份约 1.2 GB，只保留最近 5 份和各阶段末的快照。

## 8. 干预

```
fork(snapshot, patches, n_ticks) → (treated_run, control_run)
```

- 处理组与对照组从同一份快照出发，用同一组 key 同步运行；对照组的 patch 为空。
- 由于混沌，两条轨迹最终会分开。所以只分析干预后的一段窗口，并且从多个快照、多个世界重复分叉。

| patch | 作用 | 用途 |
|---|---|---|
| `clamp_direction(uids, v, value)` | 在 think 之后，把 h 在方向 v 上的分量设为给定值 | E4 |
| `ablate_sensor(uids, idx)` | 把切片中指定的维度设为常数 | H3；检验某个传感器是否必要 |
| `freeze_plasticity(uids)` | η 设为 0 | 一生学习的克隆对照 |
| `set_knob(uids, value)` | 固定档位 | H3 |
| `present(source, pos, θ)` | 在指定位置放入一个中性物体，或从任意快照复制一个个体（例如一个刚咬伤过别人的个体） | E1 的受控刺激 |
| `set_field(name, region, value, ticks)` | 局部改动某个场，例如制造一次冷暴露 | 与体温有关的特征 |
| `prevent_sleep(uids, ticks)` | 让入睡动作在一段时间内无效 | 睡眠剥夺：思维噪声、行为退化、情绪反应的变化 |
| `wake(uids)` | 强制唤醒 | 睡眠惯性；回放未完成的后果 |
| `inject_pain(uids, source, a, ticks)` | 人为设定某个噪声源的强度，身体状态保持不变 | 检验各种疼痛信号本身对行为和内部状态的作用 |
| `set_stores(uids, N, G)` | 设定营养储量或胃内容物，例如制造某一类营养的缺乏，或者让胃饱而储量空 | 特异性饥饿；饱与缺的分离 |
| `remove_entity(uid)` | 移除指定实体，例如移除亲代 | 丧失后的搜寻 |
| `transplant(uid, snapshot, pos)` | 把个体复制到另一个世界或情境 | 人格的跨情境 ICC |
| `world_param(name, value)` | 修改世界参数，例如立即切换毒素含量 | 恢复曲线、泛化 |

## 10. 实验流程

```
1 prereg/NNN-名称.md          写好后单独提交
2 configs/exp/NNN.toml        引用 prereg_id、臂、种子区间、标定记录
3 sandbox run configs/exp/NNN.toml --mode confirmatory
    运行前检查：工作区干净；prereg 的提交是 HEAD 的祖先，且早于当前时间；种子落在确认区间
    运行时记录：runs 表的全部字段
4 analysis/NNN.py             读日志，生成 results/NNN.md（引用 run_id）
5 RESULTS.md                  每条结论一行：状态（确认、探索或作废）、run_id、prereg_id
```

- **种子区间：** 探索性 < 10,000；确认性从 10,000 开始；干预从 20,000 开始。
- **探索模式**（`--mode exploratory`）不做运行前检查，但结果一律标为"探索"，不能作为确认引用。
- **预注册必须写明：**
  - 假设与否证条件；
  - 臂与种子数（每臂至少 10 个独立世界）；
  - 主指标与次指标；
  - 分析脚本路径；
  - 停止规则；
  - 标定记录编号。

## 12. 工程规则

1. **臂只能是配置。** 代码里只出现能力开关，不出现臂名。
2. **单向隔离。** sandbox 不读取任何分析结果；analysis 不被 sandbox 导入。
3. **每个提交都附上语义泄漏审查的四个问题的回答**（见 `PRINCIPLES.md` 2.4）。
4. **规则即规格。** 任何新的交互、新的实体类型或新的营养类型，都要先写进 5.1 节的营养规则或 5.4 节的判定表，配好单元测试，然后才能实现。不允许针对某一类个体写例外规则。
5. **新系统必须有单元测试和不变量。**
6. **一个提交只做一件事。** 结果提交只包含 `results/` 和 `RESULTS.md`。
7. **常驻文档只有五份：** PRINCIPLES、SANDBOX、ARCHITECTURES、EMOTIONS、RESULTS。其他文档按编号放进 `prereg/` 和 `results/`。EMOTIONS 只用于分析，任何代码都不得引用它的内容。
8. **先通过里程碑验收，再跑确认性实验。**
9. **宽度由布局推导。** 基因组宽度、快权重宽度等数组尺寸从脑布局推出（§6.3），不写死在配置里；D 或 H 变化时不得手改两个数。
